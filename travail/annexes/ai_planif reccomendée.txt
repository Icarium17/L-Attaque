Ordre logique optimal (structure globale)

Je regroupe ton plan en grandes phases cohérentes.

PHASE 0 — Fondations techniques

	Serveur :

	Installation serveur

	Création base de données

	Classes de base : User/Player, Board, Piece, Move

	GameManager (structure initiale)

	Contrôleur

	Structure API (réponses JSON standardisées)

	Client :

	Installation Vite

	Configuration Tailwind

	Structure React

	Routing (index, lobby, game)

	MainLayout

	Composants génériques (Button, Error)

	Objectif : application vide mais communicante.

PHASE 1 — Authentification complète

	Serveur :

	IndexAction (signup, signin, signout)

	Sessions

	Validation serveur

	Client :

	Formulaires

	Appels fetch POST

	Gestion état utilisateur

	Gestion erreurs

	À la fin : authentification complète et stable.

PHASE 2 — Moteur de jeu minimal (sans IA, sans multijoueur)

	Serveur :

	Validation des déplacements

	Système de combat

	Conditions de victoire

	GameManager fonctionnel

	gameAction

	Client :

	Composant Board (affichage simple)

	Composant Piece

	Placement initial

	Mise à jour après action

	PlayerInfo

	À la fin : jeu fonctionnel en mode solo contrôlé par le serveur.

PHASE 3 — IA

	Serveur :

	AIPlayer

	BeliefState

	Node / InfoSet

	MCTS

	Niveaux de difficulté

	Client :

	Sélection difficulté

	Gestion tour IA

	Feedback visuel

	Important : l’IA dépend totalement d’un moteur de jeu stable.

L’ordre optimal est :

	Fondations

	Authentification

	Moteur solo stable

	IA

	Multijoueur

	Systèmes annexes

Le plus grand risque serait de commencer l’IA ou le multijoueur avant que le moteur de jeu soit parfaitement stable.
